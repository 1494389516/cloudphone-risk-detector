# CloudPhoneRiskKit 服务等级协议 (SLA)

> 版本: 7.3 | 生效日期: 2026-03-27 | 审核周期: 每季度

---

> ## ⚠️ 指标性质声明（务必先读）
>
> 本文档中所有**检测精度指标**（TPR / FPR / FNR）与**性能指标**（P50/P95/P99 延迟、冷启动、内存、体积）均为 **🎯 目标值（target）**，来源为**模拟器环境估算 + 单元测试趋势观察**，**真机大规模实测数据尚未采集**。
>
> 这意味着：
> - **不要把表中数值当作"已达成的实测承诺值"**。它们是设计目标与回归基线，不是线上 SLA 达成证据。
> - **真机命中率与延迟应以 Release 构建、真实设备、可复现实验矩阵为准**；模拟器只适合趋势观察（与 `OPEN_SOURCE_READINESS.md` §2、§6 一致）。
> - 第 9 节"违约与补偿"的违约阈值在**真机基线建立前不具备可执行性**——没有实测基线就无法判定是否违约。
> - 对外正式承诺 SLA 前，必须先按第 8 节 + `OPEN_SOURCE_READINESS.md` §6 的样本矩阵完成真机基准采集，再把"目标值"逐项替换/确认为"实测达成值"。
>
> 下文表格中以 **🎯目标(模拟器估算,真机未实测)** 标注的列，均属此性质。

## 1. 检测精度 SLA

### 1.1 核心指标

> 下表 **承诺值** 列均为 🎯**目标值(模拟器估算,真机未实测)**，非实测达成值。详见文首"指标性质声明"。

| 指标 | 定义 | 🎯目标值(模拟器估算,真机未实测) | 度量方式（真机实测落地后采用） |
|------|------|--------|---------|
| **真阳性率 (TPR / Recall)** | 实际风险设备被正确标记为高风险的比例 | **≥ 99.2%（目标）** | 月度红蓝对抗 + 线上标注回溯 |
| **误杀率 (FPR)** | 正常设备被误判为高风险的比例 | **≤ 0.05%（目标）** | 月度全量线上统计 |
| **漏杀率 (FNR)** | 风险设备未被检出的比例 | **≤ 0.8%（目标）** | 月度红蓝对抗 |

### 1.2 分场景精度

> 下列 TPR/FPR 同为 🎯**目标值(模拟器估算,真机未实测)**。

| 检测域 | 🎯TPR 目标 | 🎯FPR 目标 | 说明 |
|--------|---------|---------|------|
| 越狱检测 | ≥ 99.5% | ≤ 0.02% | 11 个 Detector 覆盖 |
| Hook/注入检测 | ≥ 99.0% | ≤ 0.05% | Frida/Substrate/Dobby 等 |
| 云手机检测 | ≥ 98.5% | ≤ 0.08% | 含 vPhone 裸金属场景 |
| 调试器检测 | ≥ 99.0% | ≤ 0.03% | LLDB/GDB/dtrace |
| 重打包检测 | ≥ 99.5% | ≤ 0.01% | TeamID/签名链验证 |

### 1.3 精度度量方法

- **红蓝对抗**：每月执行一次，使用最新公开/私有越狱工具、Frida 版本、常见云手机方案进行对抗测试
- **线上回溯**：对标记为高风险的设备进行人工复核（抽样 ≥ 500 条/月）
- **自动化回归**：每个 Release 版本执行完整检测用例（301+ 单元测试）

## 2. 性能 SLA

### 2.1 核心性能指标

> 下表 **承诺值** 列均为 🎯**目标值(模拟器估算,真机未实测)**。测试条件描述的是目标值的预期采集环境，真机基准尚未落地。

| 指标 | 🎯目标值(模拟器估算,真机未实测) | 测试条件（真机实测落地后采用） |
|------|--------|---------|
| **evaluate() 耗时 P50** | < 80ms | iPhone 12+, iOS 16+, Release 构建 |
| **evaluate() 耗时 P95** | **< 200ms** | iPhone 12+, iOS 16+, Release 构建 |
| **evaluate() 耗时 P99** | < 350ms | iPhone 12+, iOS 16+, Release 构建 |
| **冷启动耗时 (start → 首次 evaluate 完成)** | **< 500ms** | iPhone 12+, iOS 16+, Release 构建 |
| **内存占用峰值** | < 15MB | 包含所有 Detector 初始化 |
| **内存占用稳态** | < 8MB | evaluate 完成后 |
| **SDK 二进制体积 (arm64)** | < 5MB | static library + strip |

### 2.2 降级场景性能

| 场景 | evaluate() P95 | 说明 |
|------|---------------|------|
| 远程配置不可用 | < 250ms | 使用本地缓存/默认配置 |
| 传感器预热中 | < 120ms | PhysicalSensorProbe 返回 pending |
| Keychain 不可用 | < 220ms | 降级到 UserDefaults |
| Kill Switch 启用 | < 20ms | 直接返回 score=0 |

### 2.3 性能测试方法

```swift
// 性能基准测试示例
func testEvaluatePerformance() {
    let kit = CPRiskKit.shared
    kit.start()

    measure {
        _ = kit.evaluate()
    }
    // Xcode 自动计算 P50/P95/stdev
}
```

## 3. 可用性 SLA

### 3.1 端侧可用性

| 指标 | 承诺值 | 说明 |
|------|--------|------|
| **SDK 初始化成功率** | ≥ 99.99% | start() 不抛出异常 |
| **evaluate() 可用率** | ≥ 99.95% | 返回有效 CPRiskReport |
| **Crash-Free Rate** | ≥ 99.99% | SDK 引入的崩溃率 |

### 3.2 降级保障

SDK 采用多层降级链确保即使部分子系统不可用也能返回有效结果：

| 层级 | 降级行为 | 对精度的影响 |
|------|---------|------------|
| 远程配置不可用 | 回退到本地缓存 → 默认配置 | 低（关键检测开关强制开启） |
| Keychain 不可用 | 降级到 UserDefaults | 极低（仅影响 deviceID 持久性） |
| 传感器不可用 | 返回 unavailable 信号 | 中（行为熵无法计算） |
| CRiskCore 不可用 | 降级为纯 Swift 评估 | 中（缺少壳保护联动） |
| 单个 Detector 超时 | 返回 score=80（高风险） | 无（fail-closed 策略） |

## 4. Kill Switch SLA

| 指标 | 承诺值 |
|------|--------|
| **Kill Switch 生效延迟** | ≤ 30 秒（已拉取远程配置的设备） |
| **Kill Switch 全量生效** | ≤ 5 分钟（所有活跃设备） |
| **Kill Switch 可用性** | 99.99% |
| **误触发概率** | ≤ 0.001% |

### Kill Switch 行为

启用 Kill Switch 后：
- `evaluate()` 返回 `score=0, action=allow`
- 所有高风险拦截立即失效
- 不影响信号采集（恢复后可立即重新评估）
- 审计日志记录 Kill Switch 状态

## 5. 事件响应 SLA

### 5.1 事件严重等级

| 等级 | 定义 | 示例 |
|------|------|------|
| **P0 / 严重** | SDK 导致 App 崩溃或大规模误杀 | Crash-Free Rate < 99.9%; FPR > 1% |
| **P1 / 高** | 核心检测能力失效 | 特定越狱工具未检出; TPR < 95% |
| **P2 / 中** | 非核心功能异常 | 行为信号不准; 性能退化 |
| **P3 / 低** | 文档/接口兼容性问题 | API deprecation; 文档错误 |

### 5.2 响应时间

| 等级 | 确认时间 | 修复方案 | 热修复/版本发布 |
|------|---------|---------|---------------|
| P0 | ≤ 15 分钟 | ≤ 1 小时 | ≤ 4 小时 |
| P1 | ≤ 1 小时 | ≤ 4 小时 | ≤ 24 小时 |
| P2 | ≤ 4 小时 | ≤ 2 个工作日 | 下一个计划版本 |
| P3 | ≤ 1 个工作日 | ≤ 5 个工作日 | 下一个计划版本 |

### 5.3 P0 事件处理流程

1. **Kill Switch 止血**（≤ 5 分钟）：立即启用 Kill Switch 停止误杀
2. **根因定位**（≤ 1 小时）：分析崩溃/误杀的根因
3. **热修复方案**（≤ 2 小时）：远程配置调整或紧急版本
4. **修复验证**（≤ 4 小时）：红蓝对抗验证 + 灰度发布
5. **事后复盘**（≤ 48 小时）：输出 RCA 报告与改进措施

## 7. 升级路径支持

### 7.1 API 兼容性保证

- **Minor 版本升级**（如 7.2 → 7.3）：100% API 向后兼容，无 breaking changes
- **Major 版本升级**（如 6.x → 7.x）：提供至少 1 个版本的 deprecation 过渡期
- **所有 deprecation** 均通过编译器 warning 提示，附带迁移说明

### 7.2 数据迁移

- Keychain 中的 deviceID 跨版本持久化
- RiskHistoryStore 数据自动迁移加密
- 基线数据在 major 升级时可能需要重建（SDK 自动处理）

## 9. 违约与补偿

### 9.1 SLA 违约定义

> ⚠️ 下表违约阈值直接引用第 1/2 节的 🎯**目标值**。在真机实测基线建立之前，这些阈值**不具备可执行性**——缺少实测达成基线就无法客观判定是否违约。本节在真机基准落地前仅作为目标对齐参考，不构成可索赔的合同义务。

| 指标 | 违约条件 | 严重程度 |
|------|---------|---------|
| TPR | < 99.2% 持续 ≥ 24 小时 | 严重 |
| FPR | > 0.05% 持续 ≥ 1 小时 | 严重 |
| evaluate() P95 | > 200ms 持续 ≥ 1 小时 | 高 |
| 冷启动 | > 500ms 持续 ≥ 1 小时 | 高 |
| Kill Switch 生效延迟 | > 5 分钟 | 严重 |

### 9.2 补偿措施

- **P0 SLA 违约**：48 小时内输出 RCA 报告 + 改进时间表
- **连续违约**：启动升级程序，提供专属技术支持通道
- **重大误杀事件**：提供事件影响范围分析 + 受影响用户识别辅助
