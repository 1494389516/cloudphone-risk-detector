# CloudPhoneRiskKit 架构设计文档

## 1. 整体架构

CloudPhoneRiskKit 是一款面向 iOS 的实时风控 SDK，用于检测云手机/模拟器环境、越狱设备和调试/篡改行为。整体架构采用**分层管道（Layered Pipeline）**设计：

```
┌──────────────────────────────────────────────────────────────────┐
│                     CPRiskKit (入口层)                            │
│  单例编排器：start/stop、evaluate、config、provider 注册          │
├─────────────┬──────────────┬──────────────┬─────────────────────┤
│  Jailbreak  │  AntiTamper  │  Providers   │  Decision           │
│  Engine     │  + AntiBypass│  (Signal)    │  Engine              │
├─────────────┼──────────────┼──────────────┼─────────────────────┤
│ 13 Detectors│ 20+ Detectors│ 19 Providers │ DecisionTree        │
│ (File,Dyld, │ FridaThread  │ DRM/Battery  │ ScenarioPolicy      │
│  Sysctl,..) │ FridaHeap    │ MountPoint   │ ComboRules           │
│             │ ObjCSwizzle  │ Hardware     │ SignalWeights         │
├─────────────┴──────────────┴──────────────┴─────────────────────┤
│         RiskScorer  →  RiskVerdict  →  CPRiskReport             │
├─────────────────────────────────────────────────────────────────┤
│  Storage (AES-GCM) │ Config (Remote+Signed) │ Network │ Logger  │
└─────────────────────────────────────────────────────────────────┘
```

## 2. 核心模块

### 2.1 CPRiskKit（入口层）

- **单例**: `CPRiskKit.shared`
- **职责**: 生命周期管理（start/stop）、评估编排、远程配置、Provider 注册
- **线程模型**: `evaluateQueue`（QoS .utility）+ `stateLock`（NSLock）保护可变状态
- **Actor 支持**: `RiskEvaluationActor` 提供编译期线程安全的 async/await 评估入口

### 2.2 检测器层（Detector Layer）

所有检测器遵循统一协议：

```swift
public protocol Detector {
    func detect() throws -> DetectorResult
}
```

检测器通过 `DetectorRegistry` 注册和管理，支持：
- **工厂模式**: 按需创建检测器实例
- **分组管理**: jailbreak / antiTamper / integrity 三大组
- **信号去重**: 同一 `signalOverlapGroup` 内取 max score
- **元数据清单**: iOS 版本兼容、依赖关系、冲突解决、优先级
- **封印机制**: `seal()` 后拒绝运行时注入
- **可测试性**: `DetectorRegistering` 协议支持 Mock 注入

#### 检测器分类

| 分组 | 检测器数量 | 代表检测器 |
|------|-----------|-----------|
| Jailbreak | 13 | FileDetector, DyldDetector, HookDetector |
| AntiTamper | 20+ | FridaDetector, DebuggerDetector, AntiTamperingDetector, MIEPostureDetector（sysctl 设备级 MTE/EMTE 姿态，通常仅 A17 / A17 Pro 及后续较新产品线更可能暴露相关位形） |
| Integrity | 3 | CodeSignatureValidator, MemoryIntegrityChecker, RuntimeIntegrityValidator |
| AntiBypass | 2 | MultiPathFileDetector, RuntimeIntegrityValidator |

### 2.3 信号提供者层（Signal Provider Layer）

```swift
public protocol RiskSignalProvider: AnyObject {
    var id: String { get }
    func signals(snapshot: RiskSnapshot) -> [RiskSignal]
    func serverSignals(snapshot: RiskSnapshot) -> ServerSignals?
}
```

19 个内置 Provider，覆盖：
- **硬件指纹**: VPhoneHardware, DeviceHardware, HardwareCapability, DisplayMux
- **行为分析**: BatteryEntropy, IMUNoiseSpectrum, AudioRoute
- **环境一致性**: EnvironmentConsistency, LayeredConsistency, MountPoint
- **云手机检测**: CloudPhoneEnvironment（网络延迟、屏幕分辨率、热状态、进程名、时区一致性）
- **安全验证**: DRMCapability, BiometricState, BasebandIsolation, AppAttest

Provider 注册表同样支持封印机制，封印后篡改尝试会注入 `provider_tamper_attempt` 信号。

### 2.4 决策引擎层（Decision Engine）

`RiskDetectionEngine` 是一个 `Sendable` struct，评估管道为：

```
Signal Collection → Fast Digest → Score & Force → Tree Commit → RiskVerdict
```

1. **Signal Collection**: 从所有 Provider 收集信号，合并额外信号
2. **Fast Digest**: 高置信度信号快速短路（跳过完整评估）
3. **Score & Force**: 加权评分 + 强制规则匹配
4. **Tree Commit**: DecisionTree 场景化决策 + ComboRules

输出四级判决：`allow` / `challenge` / `stepUpAuth` / `block`

### 2.5 存储层

- **SecureFileStore**: AES-GCM 加密文件存储
- **RiskHistoryStore**: 风险评估历史（FreshnessAnchor 新鲜度锚）
- **StorageIntegrityGuard**: Keychain 完整性保护
- **DualPathBaselineStore**: 双路径基线存储

### 2.6 配置层

- **RemoteConfigProvider**: 远程配置拉取（签名验证 + 版本回滚保护）
- **ConfigSignatureVerifier**: HMAC-SHA256 配置签名验证
- **ConfigCache**: 本地配置缓存（NSRecursiveLock 保护）

### 2.7 二进制加固层（cprisk-armor · ABI v3）

- **控制流平坦化（CFF · Pass 9）**: 关键函数 state-machine 混淆；dispatcher 变体由 `buildSeed ^ 0xD15C_4ED1_5D15_C4ED` 派生的 per-function RNG 决定，消除静态模板特征；B.cond/PACIASP/PACIBSP 块边界在 v7.4 修复（CFF#23/#24）
- **指令替换（Pass 8）**: Mach-O 二进制指令级 1:1 等长语义等价替换
- **白盒 PRF（ABI v3）**: 9 域 table-driven SPN，~160KB S-box（8-bit 升级自 v7.4）；per-string KDF `HMAC(key, "cprisk.str.key.v1" || sid || nonce)` 与 configDigest 标签+长度前缀格式在 Swift/C 两侧锁步
- **VMProtector（Pass 13 · M3）**: ARM64→自定义字节码虚拟化；8-bit S-box 字节码已在 v7.4 重建
- **反调试（Pass 7 + CRiskCore）**: ptrace deny-attach、exception handler 注册、multi-probe watchdog；anti-dump 探针 [2,9]s 随机抖动、Mach 端口 8 样本基线校准（v7.4 加固）
- **完整性校验**: __TEXT.__text 段哈希 + configDigest 双端验证（v7.4 修复 Swift/C 格式不一致）

### 2.8 检测链证明层（v7.4 新增）

`cprisk_detection_attest` 提供 per-session HMAC 滚动证明，将检测执行顺序与结论绑定为可被服务端独立验证的密码学标签：

```
cprisk_attest_session_begin(nonce[16])          // 白盒 PRF Domain 5 派生密钥 + 新鲜 nonce
  │
  ├─ for each Detector:
  │    cprisk_attest_record(id, score, methods_hash)  // chain = SHA256(prev || id_le4 || score_le4 || hash)
  │
cprisk_attest_session_finalize(tag[32], count)  // tag = HMAC(key, label || nonce || chain || count_le4)
```

- **DetectorID 枚举化**: 每个检测器分配固定 `UInt8` ID（如 `0x23=debugger`），消除明文字符串标识符旁路
- **金丝雀槽（id=0x7F, score=13）**: 每次 detectV2 结束后验证，确认证明链未被截断
- **method 标签注入**: `attest_nonce:...` / `attest_count:...` / `attest_tag:...` 随 RiskReport 上报，服务端可独立重算验证

## 3. 数据流

```
App 调用 evaluate()
  │
  ├─→ 解析运行时配置 (resolveRuntimeConfig)
  ├─→ 强制安全下限 (enforceSecurityFloor)
  ├─→ 注册 Providers (registerProviders)
  ├─→ 封印注册表 (seal)
  ├─→ CRiskCore 初始化 (deny_attach + exception_handler)
  ├─→ Armor 运行时启动 (ensureArmorRuntimeStarted)
  │
  ├─→ 构建 RiskContext (buildRiskContext)
  │   ├─→ JailbreakEngine.detect() → DetectorRegistry.detectAll()
  │   ├─→ TouchCapture / MotionSampler 行为数据
  │   └─→ NetworkSignals 网络数据
  │
  ├─→ 构建 RiskSnapshot
  ├─→ 收集 ServerSignals
  ├─→ 图风控特征 (GraphFeatureCollector)
  │
  ├─→ RiskDetectionEngine.evaluate()
  │   ├─→ collectAndAugmentSignals()
  │   ├─→ fastDigest() → 可能短路
  │   ├─→ scoreAndForceDecision()
  │   └─→ treeCommitVerdict()
  │
  └─→ CPRiskReport 返回
```

## 4. 线程安全模型

| 机制 | 使用位置 | 说明 |
|------|---------|------|
| NSLock | 35+ 处 | 主要状态保护机制 |
| UnfairLock | Signal 收集超时 | 高频路径优化（2-3x 快于 NSLock） |
| NSRecursiveLock | ConfigCache | 嵌套锁场景 |
| DispatchSemaphore | 6 处 | 超时协调（Detector/Provider 执行） |
| DispatchQueue | 7 处 | Detector 执行、信号收集、传感器预热 |
| Actor | RiskEvaluationActor | 编译期线程安全的评估入口 |
| Sendable | RiskDetectionEngine 等 | struct 级别不可变保证 |

## 5. 检测链完整性证明

`JailbreakEngineV2.detectV2` 在完成所有检测器执行后调用 `cprisk_attest_session_finalize`，将当次会话的检测结果（ID 序列 + 各 Detector score + methods SHA-256 摘要）打包成一个 32 字节 HMAC 标签随报告上报。

**设计目标**：Swift 层（检测器调用链）被 Hook 时，C 层的 HMAC 证明链仍然可以暴露结论与执行顺序的不一致，防止攻击者仅 hook Swift 侧即可静默清零检测结果。

**会话边界**：每次 `detectV2` 调用生成独立 nonce（`cprisk_attest_session_begin`），多次调用之间的证明标签不可互换。

## 6. 控制流平坦化（CFF）

关键函数（如 `DetectorRegistry.detect(type:)`）使用 CFF 保护：

```swift
// 状态编码/解码
func encodeState(_ rawState: UInt32) -> UInt32 {
    CFFStateCodec.encode(state:key:salt:style:)
}

// 运行时盐值派生
let salt = CFFRuntimeSalt.derive(functionSeed:inputs:)

// 不透明谓词分支
CFFOpaquePredicates.connectorGate(encodedState:salt:)
```

CFF 保护层级：`.light` / `.standard` / `.aggressive`

## 7. 可测试性设计

### DetectorRegistering 协议

```swift
public protocol DetectorRegistering: AnyObject {
    func detect(type: DetectorRegistry.DetectorType) -> DetectorResult
    func detect(group: DetectorRegistry.DetectorGroup) -> GroupDetectionResult
    func detectAll(enabledTypes: Set<DetectorRegistry.DetectorType>) -> ComprehensiveDetectionResult
    func register(type: DetectorRegistry.DetectorType, factory: @escaping DetectorRegistry.DetectorFactory)
    func unregister(type: DetectorRegistry.DetectorType)
    func seal()
    var isSealed: Bool { get }
    func createDetector(type: DetectorRegistry.DetectorType) -> Detector?
    func manifest(for type: DetectorRegistry.DetectorType) -> DetectorRegistry.DetectorManifest
    func isAvailable(_ type: DetectorRegistry.DetectorType, osVersion: Double) -> Bool
}
```

测试中可注入 Mock：

```swift
class MockDetectorRegistry: DetectorRegistering {
    var stubbedResult: DetectorResult = .empty
    func detect(type: DetectorRegistry.DetectorType) -> DetectorResult {
        stubbedResult
    }
    // ...
}
```

## 9. 日志与审计

### 结构化日志

```swift
Logger.debug("message", metadata: ["key": "value"])
Logger.info / .warn / .error / .critical
```

- DEBUG 模式：控制台输出 + 自定义 Destination
- Release 模式：可选启用 warn/error/critical（`Logger.releaseLoggingEnabled`）
- 自定义输出：实现 `LogDestination` 协议

### 审计追踪

```swift
Logger.audit(action: "kill_switch_activated", details: [...])
Logger.auditSnapshot() // 获取最近 200 条审计记录
```

关键决策点（killSwitch、preflight 短路、fast digest）均记录审计日志。
